# v1.0.1

Reliability release. Ends the recurring "state file out of sync with the desktop" drift class found in the 2026-07-01 deep dive: a one-time cleanup of ~130 historical artifacts stranded in active locations, durable doctor checks so the class can't silently re-accumulate, and a three-layer golden-fixture harness that pins the framework shim, the Rust IPC layer, and the frontend derivations to the same ground truth.

## Fixes

- **One-time artifact migration** ([#300](https://github.com/Eric-Ness/Tiki-V2/issues/300)) — New idempotent `migrate-stale-artifacts.mjs` (`--dry-run` supported, backup + manifest before touching anything). Archived **118 stale plan files** (issues #18–#224, phases normalized to their shipped reality), moved **11 stranded v0.2.x release defs** to `releases/archive/` as `status:"shipped"`, and reconstructed **5 ghost release defs** (v0.6.7 / v0.7.4 / v0.7.5 / v0.7.6 / v0.7.8) from history and changelog links. The desktop no longer renders February's releases as active or shipped issues as mid-flight. Also fixed stale doc-comment counts in the reconciler header.

## Features

- **Doctor: stale active-location artifact detection + Fix actions** ([#301](https://github.com/Eric-Ness/Tiki-V2/issues/301)) — `tiki_doctor` now reports `staleActivePlans` (active plan whose issue is already finished, with live activeWork correctly excluded) and the Diagnostics panel flags active-location release defs with a finished `status`, each with a one-click Fix (`archive_stale_plans` / `archive_stale_release_defs`, mirroring the migration's move semantics). Ghost-release detection widened to changelog stems (catches the v0.7.4 class that history cross-referencing misses). `unverifiedShippedCriteria` gained a 30-day recency cutoff so the pending-verification list stays actionable instead of flooding with ancient plans.

## Testing

- **State-vs-desktop drift harness** ([#302](https://github.com/Eric-Ness/Tiki-V2/issues/302)) — Nine golden fixture workspaces (`packages/shared/fixtures/tiki-workspaces/`): five canonical pipeline stages plus four drift-injection classes taken directly from #300's findings. Each fixture's `expected.json` is asserted by **three independent layers**: framework node:test drives temp copies through the real shim GET→SHIP; desktop vitest asserts every display-facing derivation; cargo asserts the serialized IPC payloads and doctor findings. A mutation meta-test proves cross-layer coupling — one corrupted fixture fails at least two layers. A new drift class becomes one new fixture instead of a bespoke guard test.

## Notes

- Test totals: shared 135 / desktop **350** (+74) / framework **186** (+15) / cargo **112** (+7); `clippy --all-targets --deny warnings` clean; lint gated at 0 errors.
- The migration ran against this repo's own `.tiki/` as part of #300 — the desktop sidebar, dependency graph, and criteria checklists now agree with `state.json` for all historical work.
- No user-facing feature changes; safe update for all users.
